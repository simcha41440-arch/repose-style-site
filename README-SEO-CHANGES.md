# עדכוני SEO לאתר Reposestyle.com — סיכום ומה נדרש ממך

## חדש: מערכת ביקורות לקוחות (לתיקון האזהרות ב-Search Console)

Search Console התריע שחסרים השדות `review` ו-`aggregateRating` בנתוני
המוצרים המובנים (Structured Data). השדות האלה **חייבים לשקף ביקורות
אמיתיות** — לכן לא הוספתי מספרים בדויים, אלא בניתי מערכת ביקורות
מלאה שתעדכן את הדירוגים אוטומטית ברגע שיהיו ביקורות אמיתיות ומאושרות:

- **בכל עמוד מוצר** יש עכשיו כפתור "כתיבת ביקורת" שפותח טופס (שם,
  דירוג בכוכבים, טקסט, אימייל לאימות).
- הטופס נשלח בסיום ל**שירות Formspree** (חינמי עד 50 הגשות בחודש) —
  כל ביקורת מגיעה אליך במייל לאישור לפני פרסום, בדיוק כמו שעושים
  אתרי מותגים יוקרתיים (ביקורת מאומתת ומבוקרת, לא פתוחה לכולם).
- **שלבים שאתה צריך לבצע כדי להפעיל את זה בפועל:**
  1. הירשם בחינם בכתובת https://formspree.io ופתח טופס חדש.
  2. Formspree ייתן לך כתובת מסוג `https://formspree.io/f/xxxxxxx` —
     העתק אותה.
  3. בקובץ `rstyle-site-luxury-gold.html`, חפש את השורה:
     `const REVIEW_FORM_ENDPOINT = "https://formspree.io/f/YOUR_FORM_ID";`
     והחלף את `YOUR_FORM_ID` בכתובת שקיבלת.
- **כשמגיעה אליך ביקורת ואתה מאשר אותה לפרסום**, חפש בקובץ את
  האובייקט `const REVIEWS = { ... };` (ליד `PRODUCTS.push(...TOWELS_DATA);`)
  והוסף שורה למוצר המתאים, למשל:
  ```js
  const REVIEWS = {
    prachim: [
      { name:"מיכל כהן", rating:5, text:"מצעים מדהימים, איכות מעולה!", date:"2026-08-05", verified:true }
    ]
  };
  ```
  מפתח האובייקט (`prachim` בדוגמה) הוא ה-`sku`/מזהה של המוצר —
  אפשר למצוא אותו בקטלוג ב-`const PRODUCTS = [...]` בשדה `id`.
- ברגע שתוסיף ביקורת ותעלה מחדש את הקובץ לאתר: התצוגה בעמוד המוצר
  (כוכבים, ממוצע, מספר ביקורות) **וגם** נתוני ה-Schema.org
  (`aggregateRating`, `review`) יתעדכנו אוטומטית ובאופן מדויק זה לזה —
  אין צורך לחשב ממוצעים ידנית.
- **חשוב:** כל עוד אין ביקורות אמיתיות, המוצרים פשוט לא יציגו
  דירוג בכוכבים בתוצאות החיפוש של גוגל — וזה בסדר גמור. ברגע הראשון
  אזהרת "אין aggregateRating" תיעלם מ-Search Console; ברגע שתצטבר
  כמות סבירה של ביקורות היא תיעלם.

## מה תוקן בקובץ `rstyle-site-luxury-gold.html`

1. **תגיות Meta ו-Open Graph** — נוספו `title`, `description`, `keywords`,
   `canonical`, Open Graph ו-Twitter Card עם "רפאוז סטייל" / "Repose Style" /
   "Reposestyle" כמילות מפתח.
2. **Schema.org (JSON-LD)** — נוספו בלוקים מסוג `Organization` ו-`WebSite`
   בראש הדף, כדי לעזור לגוגל לקשר את שם המותג לדומיין הרשמי.
3. **ניתוב לפי כתובות אמיתיות (History API)** — האתר היה, ונשאר, אתר
   עמוד-יחיד (Single Page Application): כל ה"עמודים" (בית, קטלוג, אודות
   וכו') הם למעשה `<div>`ים שמוסתרים/מוצגים ע"י JavaScript מתוך קובץ HTML
   אחד. הוספתי שכבת ניתוב שגורמת לכתובת ה-URL בדפדפן להשתנות בפועל בכל
   מעבר עמוד (`/shop`, `/about`, `/contact` וכו'), ומטפלת בכפתורי
   "קדימה/אחורה" של הדפדפן כראוי. גם כותרת הדף ותיאור ה-Meta מתעדכנים
   דינמית לכל "עמוד".
4. **מפת אתר וקובץ robots** — נוספו `sitemap.xml` ו-`robots.txt` עם רשימת
   הכתובות המרכזיות באתר.

## מה שאתה חייב לעשות בצד השרת/אחסון — **קריטי**

מכיוון שהאתר הוא קובץ HTML בודד, הכתובות החדשות (כמו
`reposestyle.com/shop`) **אינן קיימות כקבצים בפועל בשרת**. אם מישהו
יקליד את הכתובת הזו ישירות, ירענן את הדף, או אם Google ינסה לגשת אליה
ישירות — השרת יחזיר שגיאת 404, אלא אם תגדיר "SPA fallback": כלל שאומר
לשרת להגיש תמיד את אותו קובץ HTML הראשי, לא משנה מה הנתיב המבוקש.

צעדים נדרשים:

1. **העלה את הקובץ `rstyle-site-luxury-gold.html` בתור `index.html`**
   בשורש האתר (זה השם שרוב אירוח האתרים מצפה לו).
2. הגדר את כלל ה-Fallback המתאים לספק האחסון שלך:
   - **Netlify**: קובץ `_redirects` מצורף (עדכן את שם הקובץ בתוכו אם לא
     קראת ל-HTML הראשי `index.html`).
   - **Apache**: קובץ `.htaccess` מצורף.
   - **Nginx**: הוסף ל-`server` block:
     `try_files $uri $uri/ /index.html;`
   - **Vercel**: הוסף `vercel.json` עם `rewrites` ל-`index.html`.
3. העלה גם את `sitemap.xml` ו-`robots.txt` לשורש הדומיין
   (`reposestyle.com/sitemap.xml`, `reposestyle.com/robots.txt`).
4. הירשם ל-**Google Search Console**, אמת בעלות על `reposestyle.com`,
   והגש שם את כתובת ה-Sitemap.

בלי הצעד הזה, השינויים בניתוב לא רק שלא יעזרו — הם עלולים לגרום ל-404
אמיתי למי שינווט ישירות לכתובת פנימית או ירענן דף.

## חשוב להבין — מה השינויים האלה *לא* יכולים להבטיח

אני רוצה להיות כן לגבי הציפיות, כדי שלא תתאכזב:

- **מיקום ראשון בגוגל אינו דבר שניתן להבטיח בקוד.** דירוג תלוי בעשרות
  גורמים מחוץ לקוד עצמו — גיל הדומיין, כמות ואיכות קישורים נכנסים
  (backlinks), תעבורת גולשים, תוכן ייחודי, מתחרים בתחום ועוד. השינויים
  שביצעתי הם תנאי הכרחי (בלעדיהם גוגל לא יבין את האתר נכון), אך לא
  תנאי מספיק.
- **Sitelinks (תת-הקישורים מתחת לתוצאת החיפוש) נקבעים אוטומטית ע"י
  האלגוריתם של גוגל** על סמך מבנה אתר ברור, פופולריות ותעבורה — ולא
  ניתן "להזמין" אותם או להכריח את הופעתם ע"י קוד. מה שכן אפשר, וזה מה
  שעשיתי, זה לתת לגוגל את כל האותות הנכונים (מבנה ניווט תקין, כתובות
  ייחודיות, מפת אתר, Schema) כדי להגדיל את הסיכוי שהם יופיעו עם הזמן.
- **מכיוון שהאתר הוא JavaScript-בלבד (Client-Side Rendering)**, גוגל
  צריך להריץ את ה-JavaScript כדי לראות את התוכן בכל "עמוד" — הוא כן
  יודע לעשות זאת ברוב המקרים, אך זה תהליך פחות אמין ואיטי יותר מאשר
  אתר עם עמודי HTML נפרדים ואמיתיים לכל כתובת (Static Multi-Page או
  Server-Side Rendering). לתוצאות SEO הכי חזקות בטווח הארוך, כדאי לשקול
  בעתיד מעבר לאתר עם דפים נפרדים אמיתיים (למשל בעזרת פריימוורק כמו
  Next.js או ע"י יצירת קבצי HTML נפרדים לכל עמוד).

## שאלות שכדאי לשקול

- **אם `reposestyle.com` עדיין לא באוויר (Live) ומאונדקס בגוגל** — שום
  שינוי בקוד לא ישפיע עד שהדומיין יעלה, יתווסף ל-Search Console, וגוגל
  יסרוק אותו בפועל. זה יכול לקחת מספר ימים עד שבועות.
